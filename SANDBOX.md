# Sandbox intake process

New projects join the Sheet-Native Computing Foundation at the **Unsaved Draft** tier (our
Sandbox). The process is deliberately light — ambition is the main prerequisite.

## How to propose a project

1. Open a **[New Project Proposal](../../issues/new?template=new-project-proposal.yml)**.
2. Describe what it is, which category it belongs to, and how it reconciles.
3. Name a sponsor — any existing SNCF project or maintainer will do.
4. The Technical Oversight Cell reviews it at the next reconcile.

## Acceptance criteria (Unsaved Draft)

- It is, or intends to be, Sheet-Native (a spreadsheet is somewhere in the source of truth).
- It has a name that puns acceptably.
- It has an owner who will answer an issue this decade.
- It does not duplicate an existing project without a good joke to justify it.

## After acceptance

- The project is added to the [SNCF Landscape](https://sncfoundation.github.io/landscape.html)
  at the Unsaved Draft tier, with a logo.
- It gets a tracking issue and, when it grows up, its own repository.
- Promotion to Autosaving and Load-Bearing follows the rules in
  [GOVERNANCE.md](GOVERNANCE.md).

That's it. Everything starts as an Unsaved Draft. It reconciles from there.
